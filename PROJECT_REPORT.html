ABSTRACT

Misplacing personal belongings such as student ID cards, electronics, keys, water bottles, and academic stationery across university buildings is a recurring challenge on campus. Traditional recovery relies on fragmented physical notice boards, word of mouth, or unorganized messaging groups, leading to low recovery rates and delayed handovers.

The Campus Lost & Found Portal (SAIU PROJECTS) is a full-stack web application built to centralize lost-and-found reporting, verification, and recovery for Sai University students, faculty, and security administrators. The frontend uses HTML5, CSS3 (dark glassmorphic responsive UI), Vanilla JavaScript, and Chart.js, while the backend is powered by Node.js and Express.js with RESTful APIs secured by JSON Web Tokens (JWT) and bcrypt password hashing. Persistent storage is managed in MongoDB (supporting both MongoDB Atlas Cloud and Local MongoDB via Mongoose, with an automatic in-memory fallback for high availability).

Key implemented features include university-domain-restricted authentication (@saiuniversity.edu.in), embedded owner metadata and unique tracking reference codes (SAIU-LF-XXXX) on every item, duplicate-report detection, an intelligent Scan Found Item engine combining keyword/reference matching with in-browser perceptual image fingerprinting (64-bit dHash and dominant color analysis), an ownership-claim approval workflow, and an Administrative Console featuring recovery charts, student login audit trails, and CSV export. Automated Newman API testing (18 requests, 25 assertions, 100% pass rate) and live browser testing on Render verified production readiness.

CHAPTER 1: INTRODUCTION

1.1 Project Overview

SAIU PROJECTS — Campus Lost & Found Portal is a full-stack, database-driven web application designed specifically for the Sai University community. It provides a unified digital directory where students, faculty members, and campus security administrators can report lost or found belongings, search and filter active listings by campus building or category, scan found items using keywords or camera/uploaded photos to locate owners, submit verified ownership claims, and manage handovers through a role-segregated dashboard.

The application is deployed live on Render (https://lost-found-website-sai-university.onrender.com/) and backed by MongoDB Atlas Cloud, ensuring anytime access across desktop and mobile browsers.

1.2 Problem Statement

Across a multi-building university campus comprising Academic Blocks, Libraries, Computer Science Labs, Dining Halls, Auditoriums, and Sports Complexes, students frequently misplace valuable items such as RFID ID cards, laptop chargers, wireless earbuds, calculators, wallets, and water bottles. Currently, finding or returning these items suffers from three major difficulties:

  • Information Silos: Lost items are reported verbally at different security desks or scattered across informal group chats, making it difficult for finders to locate the rightful owner.
  • Lack of Ownership Verification: Without structured claim verification and contact tracking, items risk being handed over without proof of ownership or audit records.
  • No Visual or Location-Based Matching: Students who find an unlabeled item have no rapid way to check whether a matching lost report already exists in a centralized campus database.

1.3 Project Scope

Included in the Current Version:

  • Unified campus authentication (Sign In, New Student Registration restricted to saiuniversity.edu.in emails, and self-service password reset).
  • Full CRUD management for Lost and Found item listings across 8 campus buildings and 8 item categories, with embedded owner details, unique reference codes (SAIU-LF-XXXX), and live view counters.
  • Smart Item Scanner supporting camera capture, photo upload, in-browser perceptual image hashing (dHash), dominant color detection, keyword/reference-ID matching, and 1-click report pre-filling.
  • Ownership Claim & Verification workflow (submit proof, approve/reject handover, direct Email/WhatsApp/Call contact).
  • Role-Based Admin Console with Chart.js analytics, Student Database & Login Audit Trail (session timestamps, IP, user-agent), clickable student profile item inspection, and CSV export.

Outside the Current Scope: Automated email/SMS push notifications via external paid gateways (SMTP/Twilio), native iOS/Android mobile binaries, and automated CCTV hardware integration.

CHAPTER 5: SYSTEM DESIGN AND ARCHITECTURE

5.1 System Architecture

The application follows a layered three-tier Client–Server–Database architecture. The browser client communicates over HTTPS/JSON with the Express.js REST API, which enforces JWT authentication and role-based access control before reading or persisting documents in MongoDB via Mongoose (with automatic fallback to the resilient in-memory store).

Figure 5.1: Three-Tier System Architecture of Campus Lost & Found Portal

5.2 Data Flow / Workflow

Information flows through three primary user journeys: (1) Authentication validates @saiuniversity.edu.in credentials, logs the session, and issues a JWT; (2) Reporting & Scanning stores items with ownerDetails and imageHash, enabling visual/keyword owner lookup; and (3) Claim & Handover verifies proof and transitions items to resolved.

5.4 Module Description

  • Authentication Module (routes/authRoutes.js): Handles registration with saiuniversity.edu.in enforcement, login with role detection and persistent session logging, profile retrieval, and password reset.
  • Item & Visual Scanner Module (routes/itemRoutes.js): Manages item CRUD, text/category/building filtering, duplicate checks, view-count increments, and multi-signal scanning (dHash + color + keyword + Ref ID).
  • Claims & Verification Module (routes/claimRoutes.js): Handles claim submission, prevents self-claims, and authorizes reporters or admins to approve/reject claims and update item status.
  • Admin Analytics & Audit Module (routes/adminRoutes.js): Aggregates building/category metrics, serves full item inventory, and exposes student database & login audit logs strictly to admin accounts.

CHAPTER 9: CONCLUSION AND FUTURE SCOPE

9.1 Conclusion

The Campus Lost & Found Portal (SAIU PROJECTS) successfully addresses the fragmented recovery process at Sai University by delivering a secure, responsive, and database-driven full-stack solution. All core objectives—university-domain authentication, full CRUD item management with embedded owner details, visual and keyword-based item scanning, ownership claim verification, and role-based administrative analytics and audit logging—were achieved and verified through automated Newman API tests and live cloud deployment testing on Render.

9.2 Limitations

  • In-Browser Visual Matching Scope: The 64-bit dHash algorithm excels at matching identical or near-identical photos and dominant colors, but does not perform deep semantic object classification across drastically different camera angles or lighting.
  • No Automated Email Dispatch: Contacting an owner or claimant opens the user’s default mail client, phone dialer, or WhatsApp rather than sending automated background emails from the server.
  • Fallback Synchronization: When running in offline in-memory fallback mode during temporary database outages, new writes reside in server memory until MongoDB connectivity is restored.

9.3 Future Scope

  • Automated Email & Push Notifications: Integrate Nodemailer or Web Push API to alert students immediately when a matching item or claim is submitted.
  • Cloud Object Storage (AWS S3 / Cloudinary): Offload uploaded item photographs from base64 strings to dedicated CDN object storage for smaller database documents.
  • AI Vision Embeddings: Integrate lightweight TensorFlow.js / CLIP embeddings for angle-invariant visual similarity search.
